# AI 产品采集与增量简报

采集公开新闻的标题、链接、来源和时间，不抓全文，也不需要模型 Key。使用 Python 3.10 或更新版本，仅依赖标准库。模块不会创建或修改定时任务。

```sh
# 先用独立目录运行离线虚构演示。
python3 bin/collect.py --demo --data-dir demo/data
python3 bin/build_data.py --data-dir demo/data

# 真实采集使用另外的目录。
cp config.example.json config.json
python3 bin/collect.py --config config.json
```

默认真实采集结束后在同一采集锁内构建本模块 `site/`，即使全源失败也更新失败提示；采集失败或构建失败返回非零状态。自定义 `--data-dir` 不会隐式覆盖默认站点；可指定 `--site-output-dir` 同步构建，或手动给构建器传相同的 `--data-dir`。真实配置、日报、日志和生成的网页属于本机运行资料，不随源码或 ZIP 发布。

## 默认采集入口

默认直接采集量子位、IT之家、OpenAI News、Google AI Blog、Claude Code Releases、Hugging Face Blog、NVIDIA Blog、MIT Technology Review AI、TechCrunch AI 和百度 AI 热搜，共 10 个入口。原有 23 组 Google News 查询保留为可选来源，不再默认调用；用 `--source google-01` 等明确指定，或在本机配置 `enabled_sources`。既有显式来源列表仍按原选择执行。

量子位、IT之家与百度直连，海外来源按已配置代理或显式直连；原有代理故障时直连回退设置保持不变。IT之家与 NVIDIA 为综合新闻源，仅收录标题中含 AI 或相关模型、技术名称的文章；标题关键词可能漏掉未明确提及的报道，也可能保留相关性不足的结果。来源状态 empty 表示请求解析成功但无可收录条目；其中 duplicate_only 表示条目均已由其他来源收录，均不等于请求失败。

国内源默认归入国内 AI，海外源默认归入国际 AI；仅当标题明确出现硬件关键词，或同时出现人物姓名与发言词时，才分类到硬件或人物栏目。标题分类是线索，不保证完整。发布方博客和软件发行 Atom 无法替代所有媒体对厂商、负面事件、国内产品和人物言论的报道；各来源覆盖与时效各不相同，不能保证信息收全。

默认只保留发布日期位于 UTC 精确过去 48 小时的 RSS 新闻，每源最多 25 条。缺失时区、无法解析、未来或窗外日期分别拒收，不把未知时间当作今天。百度热搜缺乏可靠发布日期，使用 `published_at: null`、`observed_at` 和 `time_basis: observed` 记录观察时间。

英文词按边界匹配，避免把 `said` 或 `training` 中的字母误当 `AI`。标题按高关注负面、普通负面、正向、其他关键词分级；标签只是等待核验的线索，不能证明事件属实或等同完整舆情分析。

## 网络与状态

默认直连，不读取环境代理。需要代理时在私有 `config.json` 中填写 `proxy`，或显式传 `--proxy`；百度始终直连。默认不在代理故障时悄悄切换直连，只有 `proxy_fallback_direct: true` 才允许回退。

配置支持 `window_days`、`timezone`、`workers`、`timeout_seconds`、`retries`、`proxy`、`proxy_fallback_direct`、`max_items_per_source`，也可用 `enabled_sources` 选择源。Google 搜索 ID 为 `google-01` 至 `google-23`；默认源 ID 为 `qbitai`、`ithome`、`openai-news`、`googleai-blog`、`claude-code-releases`、`huggingface-blog`、`nvidia-blog`、`mit-tech-review-ai`、`techcrunch-ai`、`baidu`。

```sh
python3 bin/collect.py --source techcrunch-ai --source baidu --timeout 5 --retries 0
```

默认并发 4 个源，上限 8；Google 查询在同一轮串行且至少间隔一秒，每四小时轮换优先顺序以避免固定来源总排在限流之后。遇到 HTTP 429 后本轮剩余 Google 查询标记为暂缓，不立即重试或改走直连；其他来源继续采集。每次请求默认 15 秒、网络等暂时性错误最多重试 1 次，可配置 0～2 次。请求读取检查剩余总预算，限制响应体大小，并把截断响应等协议异常隔离到单个源。状态明确区分：

- `ok`：请求与解析成功，并收录有效标题。
- `empty`：成功解析，但无原始条目、无匹配或全部重复；原因另记。
- `error`：网络、HTTP、解析、协议或响应限制错误；只保留错误类别，不保存原始错误正文。

`coverage.state` 的 complete/partial/unavailable 只说明**本轮选定源**的请求与解析情况，不保证收全了所有新闻。全部源失败时返回退出码 2；存在可解析源或离线演示时返回 0。

## 同日多轮也能比较

每轮有独立 `run_id`。每份成功日报都内嵌同一 run 的 `delta`，不是把一个全局增量结果套到所有历史日期。

| 文件 | 作用 |
| --- | --- |
| `latest.json`、`最新日报.md` | 最近可用快照 |
| `previous.json` | 再上一份可用快照；失败轮不推进它 |
| `last-run.json` | 最近一次尝试，包括全部源失败 |
| `delta.json`、`增量简报.md` | 对应最近一次尝试的差异摘要 |
| `YYYY-MM-DD.json`、`YYYY-MM-DD.md` | 当天最近可用快照，同日成功轮覆盖更新 |
| `seen-index.json` | 最多 14 天、10,000 项的已见内容索引 |
| `.collection-state.json` | 单次原子提交的成功快照、上一快照和索引，用于恢复派生文件 |

内容 ID 绑定去掉追踪参数后的 URL；归一化标题别名用于减少相同标题换来源后重复刷屏，不把不同 URL 强行证明为同一现实事件。同 URL 标题或关键词标签变化记为 `changed`；来源、分类、顺序和观察时间变化不记作内容变化。

有可用近期基线时，`delta` 包含 `new_ids`、`changed_ids`、`unchanged_ids` 与对应计数。当前窗口没有基线时，条目标记 `baseline`，不会假装与上一轮比较后得出了“新增”。`baseline_reason` 区分 missing、expired、future、available。最近成功快照超过 14 天或来自未来时不能作为有效比较基线。

已见索引保留最多 14 天、10,000 个 URL 身份、每项 8 个哈希别名。来源暂时缺失或本轮只采部分源后，恢复出现的已见标题不会轻易再标为新增；没有“消失事件”推断。索引失效时明确说明退回上一有效快照重建。`changed` 表示标题或标签的指纹变化，仍需阅读原文才能判断是否出现实质进展。

全部失败，或部分源失败且没有任何可用条目而已有旧快照时，`comparison_skipped: true`，不推进成功快照、previous 或已见历史；旧内容不可当成本轮新消息。写入成功 checkpoint 后，扁平 JSON 和 Markdown 都是可恢复视图；中途中断后，下轮会从 checkpoint 恢复，避免已见索引超前导致静默漏报。单个输出文件有 24 MiB 上限。

## 目录隔离

模式标记、快照和增量都记录 `module_id: ai-opinion` 与 `is_demo`。演示与真实数据双向拒绝混用，也拒绝误用车圈模块数据。只有旧 Markdown、无法确认模块身份或损坏状态的目录需要人工复核或改用新目录，不猜测迁移。`.collect.lock` 拒绝同目录并发运行；异常退出后，只在确认没有采集进程时移除残留锁。

数据不会自动发送到 LLM。需要文字简报时，由用户选定的 Agent 按模块提示词读取必要资料；定时任务应由用户另行显式设置。定时频率不构成源可用性或结果质量保证。

## 合并卡与重复报道日期

看板把同 URL、归一化后相同标题，以及主体和数字一致且文本高度相近的标题合为一张卡，保留每个来源和原文链接。不同主体、明确冲突数字或仅共同提到 AI，不足以合并。另有两类有界强同题锚：法域、起诉方向和被告一致的政府诉讼；Cursor、Fireworks、访问密钥泄露或被盗、Claude Code 扩展同时出现的安全报道。不同措辞仅在报道或观察时间相距不超过 48 小时、没有明确数字/版本/否定冲突时合并；缺数字不当作冲突。私人起诉、考虑起诉、相反诉讼方向以及已明确的版权与未成年人保护等不同案由会分开；未写案由本身不算冲突。`grouping_basis` 保留使用的文本规则。它是保守的文本去重，不能替代人工判断两篇文章是否描述同一现实事件；相同标题也可能指不同日期的同类事件。

卡片中的“连续记录 N 天”“累计记录 N 天”统计**本机已存日报里同题报道出现的日期**，不代表事件持续了 N 天。同日多轮只算一天；日期缺失不补齐。连续天数是截至最近记录日的尾段，累计天数是当前 14 日窗口中已记录日期的数量。可展开查看实际日期、首次与最近记录、标题或关键词变化记录；缺失的历史一律未知。首次记录可以早于当前窗口，不等于事件发生或发布时间。

`story-history.json` 是有界的本机文本簇索引（最多 14 日、5,000 簇），与成功快照一起原子提交到 `.collection-state.json`。失败轮不新增出现日期。原版本已有的同模块 JSON 日报可以提供真实的历史日期；只有 Markdown 或无法确认模式的数据不会被猜测导入。历史网页仅用该快照当时可知的日期，不把未来出现记录套到过去。

原始 `items` 和绑定当前 run 的 `delta` 继续保留各自身份；展示层使用 `groups` 合并卡。旧题换来源或新增链接会补充来源，不因此变成一条新事件；同 URL 的标题或关键词变化仍显示“有变化”，需要打开原文核实其事实意义。

打开日期时，有新增或变化就先显示增量，否则自动显示全量并解释原因。手动选择会按快照保留，语言和筛选切换不会覆盖它；手选增量但没有匹配内容时可直接“查看全量”。
